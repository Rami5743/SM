# שפת SM

התיעוד המחייב. במקום שבו המסמך הזה סותר כל מסמך אחר, המסמך הזה גובר —
ובכלל זה [`INVENTORY.md`](INVENTORY.md), שמתאר את המימוש *שסופק*, והחומר
שב‑[`../reference/`](../reference/), שהוא תיעוד היסטורי ואינו מתוחזק.

כל נקודה שבה התיעוד הזה סוטה מאותו חומר רשומה, עם הנימוק שלה,
ב‑[`CORRECTIONS.md`](CORRECTIONS.md) כ‑**C1**–**C8**. הסימונים האלה מופיעים
למטה במקומות שבהם הם חלים.

SM היא מכונת מחסנית, חלופה למכונה הווירטואלית של הקורס, והיא מכוונת לאותו
מחשב `Hack`. הקורס הוא

<p dir="ltr">N. Nisan and S. Schocken, <em>The Elements of Computing
Systems</em>, MIT Press, 2005.</p>

---

## 1. מבנה לקסיקלי

### 1.1 סמלים

**סמל** מתחיל באות או ב‑`_` וממשיך באותיות, ספרות, `_` ו‑`.` (C8). שום דבר
אחר אינו סמל.

סמל אינו יכול להתחיל בספרה.

ל‑`.` אין משמעות עבור המכונה. זהו תו ככל התווים, ושם שמכיל אותו הוא שם רגיל.

### 1.2 שורות

תוכנית היא רצף של שורות. כל שורה מחזיקה פקודה אחת לכל היותר.

**רווחים וטאבים מוסרים מהשורה לפני שהיא נקראת**, בכל מקום שבו הם מופיעים.
לכן

```
? --> loop
?-->loop
? - - > loop
```

הן אותה פקודה, ו‑`<- @ x` הוא `<-@x`. לאף פקודה אין כלל רווחים משל עצמה.

`//` פותח הערה, שנמשכת עד סוף השורה. ההערה מוסרת לפני שהשורה נקראת.

שורה שריקה לאחר הסרת ההערות והרווחים אינה פקודה, והיא מדולגת.

### 1.3 מספרים שלמים

קבוע שלם הוא מספר עשרוני בתחום `0..32767`. **סימן בראש הוא שגיאת תחביר**
(C5).

## 2. מודל הזיכרון

### 2.1 מרחב הכתובות של Hack

| אזור | כתובות |
|---|---|
| אוגרים | `0..15` |
| משתנים גלובליים | `16..255` |
| מחסנית | `256..2047` |
| ערימה | `2048..16383` |
| מסך | `16384..24575` |
| מקלדת | `24576` |

תוכניות SM מגיעות אל הערימה, אל המסך ואל המקלדת דרך `[]` ו‑`->[]`.

**כל ה‑RAM מאופס באתחול.** זה תואם את אמולטור המעבד של הקורס.

### 2.2 מצביע המחסנית

מצביע המחסנית נשמר ברגיסטר 0 ושמו `SP`.

`SP` מחזיק את הכתובת של **האיבר העליון** — לא של התא הפנוי הראשון. זה שונה
מהמכונה הווירטואלית של הקורס.

דחיפה למחסנית (`push`) מקדמת את `SP` ואז כותבת; שליפה מהמחסנית (`pop`)
קוראת ואז מפחיתה.

ה‑`bootstrap` קובע `SP = 255`, ולכן **מחסנית ריקה היא `SP = 255`** והערך
הראשון שנדחף נוחת ב‑`RAM[256]` (C2).

`SP` שעובר את 2047 הוא גלישה אל תוך הערימה.

### 2.3 משתנים

משתנה תופס אוגר אחד. יש שני סוגים.

**משתנים מקומיים** שייכים לפונקציה אחת. אלה הארגומנטים שלה והמשתנים
הפנימיים שלה, כולם מוכרזים יחד איתה, והם נעלמים כשהיא חוזרת. אי אפשר להגיע
אליהם מחוצה לה. מגיעים אליהם דרך `@`: `<- @x`.

**משתנים גלובליים** שייכים לתוכנית. כל פונקציה רשאית לקרוא או לכתוב כל אחד
מהם. מגיעים אליהם בלי `@`: `<- x`.

**המשתנים הגלובליים מתורגמים למשתנים רגילים בשפת אסמבלי**, והאסמבלר מקצה להם
מקום בזיכרון לפי האלגוריתם שלו. אם מספר המשתנים הגלובליים עולה על 240 אז הם
גולשים לתוך המחסנית.

## 3. פונקציות

### 3.1 מהי פונקציה

כל פונקציה לוקחת מספר כלשהו של ארגומנטים מראש המחסנית, מסירה אותם, ודוחפת
תוצאה אחת בדיוק. ייתכנו לה גם תופעות לוואי במקומות אחרים ב‑RAM.

זה נכון גם לרוב הפקודות המובנות. למשל: `+` לוקחת שתיים ודוחפת אחת.

### 3.2 הכרזה על פונקציה

פונקציה מכריזה על הארגומנטים שלה ועל המשתנים הפנימיים שלה יחד, בראשה:

```
! f(a, b) t, u
```

מכריז על `f` עם הארגומנטים `a` ו‑`b` והמשתנים הפנימיים `t` ו‑`u`. כל אחת
מהרשימות יכולה להיות ריקה.

### 3.3 קריאה וחזרה

קריאה היא שמה החשוף של הפונקציה בשורה. הארגומנטים חייבים להימצא כבר על
המחסנית, הראשון שבהם עמוק ביותר.

`<--` חוזר. הערך שיש להחזיר חייב להיות בראש המחסנית. כל מה ששייך למסגרת —
הארגומנטים, המשתנים הפנימיים, וכל מה שנשאר מעליהם — מוסר, והערך המוחזר תופס
את מקומו של הארגומנט הראשון.

### 3.4 המסגרת

המסגרת היא המקום בזיכרון שבו נשמרים הארגומנטים והמשתנים הפנימיים של
הפונקציה. המסגרת מתחילה במקום בזיכרון שנקרא `LCL`. כתובתו נשמרת ברגיסטר 1.

בתוך פונקציה בעלת `a` ארגומנטים ו‑`l` משתנים פנימיים, כאשר `LCL` הוא מצביע
המסגרת:

| | כתובת |
|---|---|
| ארגומנט `i` | `LCL + i` |
| ה‑`LCL` של הקורא | `LCL + a` |
| כתובת החזרה | `LCL + a + 1` |
| משתנה פנימי `j` | `LCL + a + 2 + j` |

קריאה דוחפת את ה‑`LCL` של הקורא ואז את כתובת החזרה. ההכרזה קובעת
`LCL = SP - (a+1)` ודוחפת `l` אפסים. החזרה שומרת את ראש המחסנית, קובעת
`SP = LCL - 1`, משחזרת את `LCL` מתוך `RAM[LCL + a]`, דוחפת את הערך השמור,
וקופצת אל כתובת החזרה.

יש מצביע מסגרת אחד (`LCL`). הארגומנטים והמשתנים הפנימיים נמצאים בהיסטים
ידועים ממנו.

### 3.5 תוויות

תוויות (`labels`) נועדו כדי לשמש יעדים לקפיצה. תווית מוכרת רק בתוך הפונקציה
שמכריזה עליה. שתי פונקציות רשאיות להשתמש באותו שם תווית.

## 4. שמות

ל‑SM ארבעה סוגי שמות, והם אינם מתנגשים זה בזה (C7):

| סוג | תחום | כיצד הוא נכתב במקום השימוש |
|---|---|---|
| מקומי — ארגומנט או משתנה פנימי | פונקציה אחת | `<- @x`, `-> @x` |
| גלובלי | התוכנית | `<- x`, `-> x` |
| תווית | פונקציה אחת | `L:`, `--> L`, `?--> L` |
| פונקציה | התוכנית | `f` |

שמות מסוגים שונים רשאים לחלוק שם. כך גם שמות של משתנים ושל תוויות בתוך
פונקציות שונות.

בתוך סוג אחד, ובתוך התחום הרלבנטי לסוג, השמות חייבים להיות שונים זה מזה.

## 5. ערכי אמת

**לכל אוגר יש ערך אמת, רק הביט המשמעותי ביותר נושא משמעות של ערך אמת.**
אוגר הוא אמת אם הביט הזה דלוק ושקר אם הוא כבוי; חמישה־עשר הביטים הנותרים
אינם נלקחים בחשבון לצורך ערך האמת של האוגר.

## 6. הפקודות

בטבלאות הבאות שלוש נקודות פירושן "וכן הלאה". השמות `x`, `f`, `loop` עומדים במקום כל סמל,
ו‑`5` במקום כל קבוע שלם.

### 6.1 מחסנית

| פקודה | פעולה |
|---|---|
| `<- 5` | דחוף את הקבוע `5` למחסנית |
| `<- x` | דחוף את המשתנה הגלובלי `x` למחסנית |
| `<- @x` | דחוף את המשתנה המקומי `x` למחסנית |
| `-> x` | שלוף אל המשתנה הגלובלי `x` מהמחסנית |
| `-> @x` | שלוף אל המשתנה המקומי `x` מהמחסנית |

`<-` חשוף ו‑`->` חשוף הם שגיאות תחביר.

### 6.2 אריתמטיקה ולוגיקה

כל אחת לוקחת את האופרנדים שלה מראש המחסנית ומחליפה אותם בתוצאה שלה.
**בכל פקודה דו־אופרנדית האופרנד העמוק יותר הוא זה שמשמאל** — `x`
ב‑`x - y`, ב‑`x < y`, ב‑`x > y`.

| פקודה | מחסנית לפני ← אחרי | משמעות |
|---|---|---|
| `+` | `… x y` ← `… x+y` | סכום |
| `-` | `… x y` ← `… x-y` | הפרש |
| `(-)` | `… x` ← `… -x` | שלילה אריתמטית |
| `~` | `… x` ← `… !x` | שלילה ביטית, (ולכן גם שלילה לוגית) |
| `&` | `… x y` ← `… x&y` | וגם ביטי (ולכן גם "וגם" לוגי) |
| `\|` | `… x y` ← `… x\|y` | או ביטי (ולכן גם "או" לוגי) |
| `==` | `… x y` ← `… b` | `b` אמת בדיוק כאשר `x = y` |
| `>` | `… x y` ← `… b` | `b` אמת בדיוק כאשר `x > y` |
| `<` | `… x y` ← `… b` | `b` אמת בדיוק כאשר `x < y` |

פקודת השוויון היא `==`. `=` בודד הוא שגיאת תחביר (C3).

### 6.3 זיכרון

| פקודה | מחסנית לפני ← אחרי | פעולה |
|---|---|---|
| `[]` | `… addr` ← `… RAM[addr]` | קרא את האוגר |
| `->[]` | `… addr value` ← `…` | `RAM[addr] := value` |

**הכתובת היא האופרנד העמוק יותר והערך נמצא למעלה** (C1) — אותו כלל כמו בכל
פקודה דו־אופרנדית אחרת, שכן הכתובת היא אגף שמאל של השמה.

שתי אלה באות במקום הסגמנטים `pointer`, `this` ו‑`that` של הקורס. מצביע הוא
ערך רגיל על המחסנית.

### 6.4 בקרה

| פקודה | פעולה |
|---|---|
| `f` | קרא לפונקציה `f` |
| `loop:` | הכרז על התווית `loop` |
| `--> loop` | קפוץ אל `loop` |
| `?--> loop` | שלוף; קפוץ אל `loop` אם הערך אמת |
| `! f(x1, x2, ...) y1, y2, ...` | הכרז על `f` |
| `<--` | חזור |

## 7. שגיאות

האמולטור והכלים שבאתר הזה מאתרים את כל מה שלהלן. **מהמתרגם של התלמיד אין
דרישה לעשות זאת**, בדיוק כפי שהקורס לעולם אינו דורש זאת מהמתרגם שלו: התוכניות שהוא מקבל
תקינות מעצם בנייתן, ומתרגם רשאי להניח שכך הדבר.

### 7.1 לפני שהתוכנית רצה

| | |
|---|---|
| קריאה לפונקציה שלא הוכרזה | C3, C7 |
| קפיצה לתווית שהפונקציה אינה מכריזה עליה | C7 |
| שתי פונקציות באותו שם | C7 |
| אותה תווית פעמיים באותה פונקציה | C7 |
| `<- @x` או `-> @x` כאשר לפונקציה אין מקומי `x` | C7 |
| סימן בראש קבוע, `<-` חשוף, `->` חשוף, `=` בודד | C3, C5 |

האחרונה שבבדיקות השמות היא בדיקה ש‑SM יכולה לעשות מוקדם יותר מהקורס.
המקומיים שלו ממוספרים, ולכן אחד מחוץ לתחום הוא תקלת זמן ריצה; שלנו נקובים
בשם, ולכן זה פשוט שם שאינו קיים.

### 7.2 בזמן שהתוכנית רצה

| | |
|---|---|
| `SP` שעובר את 2047 | המחסנית גלשה אל תוך הערימה |
| בקרה שמגיעה לסוף פונקציה בלי `<--` | C6 |

שתיהן עוצרות את התוכנית ונוקבות בשם הפונקציה. שתיהן הן מה שאמולטור המכונה
הווירטואלית של הקורס עושה.

## 8. תוכניות

### 8.1 קבצים

תוכנית היא קובץ אחד או יותר. כל אחד מהם מורכב מפונקציות שלמות: קובץ נפתח
בהכרזה, וכל פקודה שייכת לאיזו פונקציה.

*חריג אחד, להוראה בלבד.* חבילת התרגילים הראשונה משתמשת בקבצים שהם רצף חשוף
של פקודות בלי שום הכרזה, כדי שאפשר יהיה לפגוש את המחסנית ואת האופרטורים
לפני המסגרות. האמולטור מקבל `fragment` כזה ומריץ אותו כשהמחסנית היא מצבו
היחיד. הקורס נוטל לעצמו את אותו חופש ביחידה 7 שלו. מהחבילה השנייה והלאה —
רק תוכניות שלמות.

### 8.2 התחלה ועצירה

הביצוע מתחיל ב‑`bootstrap`, שקובע `SP = 255` ואז **קורא** ל‑`Sys.init`.

`Sys.init` אינו לוקח ארגומנטים. כשהוא חוזר, התוכנית נכנסת ללולאה אינסופית;
ה‑`bootstrap` הוא המקום שאליו נוחתת אותה חזרה.

רק פונקציות שאפשר להגיע אליהן מ‑`Sys.init` רצות אי פעם.

## 9. כתיבה במילים

המנמוניקות שלמעלה הן השפה והקלט היחיד שמתקבל (C4). האמולטור גם *יציג* כל
תוכנית כשפקודות המבנה מאויתות כמילים — push, pop, goto, if-goto, function,
return, label.

האופרטורים האריתמטיים והלוגיים סימבוליים בכל הצגה ולעולם אינם מאויתים
כמילים.

## 10. SM והמכונה הווירטואלית של הקורס, זו מול זו

תוכנית יכולה לעבור בין שתי המכונות, ו‑`@sm/vm` מתרגם אותה לשני הכיוונים.
מה שלהלן הוא המקומות שבהם השתיים נבדלות, והם המקומות שבהם לתרגום יש מה
לעשות. שום דבר כאן אינו חלק מ‑SM.

| | SM | המכונה הווירטואלית של הקורס |
|---|---|---|
| מצביע המחסנית | `SP` נוקב באיבר העליון; מחסנית ריקה שבסיסה 256 היא `SP = 255` | `SP` נוקב בתא הפנוי הראשון; אותה מחסנית היא `SP = 256` |
| המסגרת | מצביע אחד: ארגומנטים, ה‑`LCL` השמור, כתובת החזרה, משתנים פנימיים | חמישה: כתובת החזרה ו‑`LCL`, `ARG`, `THIS`, `THAT` השמורים |
| היכן נכתב מספר הארגומנטים | בהכרזה, `!f(a,b)` | בקריאה, `call f 2` |
| משתנה מקומי | נקוב בשם, `<- @count` | ממוספר, `push local 3` |
| עקיפין | `[]` ו‑`->[]` מעל כתובת שעל המחסנית | `pointer`, `this`, `that`, ממוקדים מחדש לפני כל שימוש |
| ערך אמת | הביט המשמעותי ביותר, ותו לא | כולו אחדות לאמת, אפס לשקר |
| `<` | `x - y`, ולכן הערך כולו הוא ההפרש | `lt`, ולכן הערך כולו הוא כולו אחדות או אפס |
| הקפיצה המותנית | `?-->` מסתעף כשהביט המשמעותי ביותר דלוק | `if-goto` מסתעף כשהערך אינו אפס |
| אחסון משותף | גלובליים, נקובים בשם, נגישים מכל מקום | `static i`, לכל קובץ שלו, נגיש רק בתוכו |
